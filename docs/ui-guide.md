# /yomimasu の UI/UX ガイド

画面を作る PR はこのガイドに従う。見本は [ui-sample.html](ui-sample.html) で、ファイルを開くだけで動く。音は出ず、録音もしない。

## 1. 考え方

文章と見本が違うときは文章に従う。文章にない見た目は見本に合わせる。どちらにもなければ、PR に判断と理由を書く。

- 見本には、形を見るために、このガイドがまだ作らないと決めた表示（決まり字までの速さの行、音量の文、例の録音への入口など）も入っている。作るかどうかはガイドの決まりに従う。
- B1、C3 などの記号は機能要件の番号である。要件の文書はリポジトリにないので、「C3 から」のような条件は、その機能の Issue が開くまで今の扱いを続ける。

| 決まり | 実装で意味すること |
| --- | --- |
| 主役は歌である | 読む画面に飾りを足さない。ボタンは歌の下に置く。歌の枠で時間とともに変わるのは、字の朱の塗りと今の区切りの囲みだけにする（7節。2026-11-04 のユーザーの判断で、帯を主役から外した） |
| コマンドは見た目で、AI は動いていない | 「考え中」「考えました」を出さない。待たせる演出を足さない |
| 1画面で押してほしいものは1つである | 塗りのボタンは1画面に1つにする |
| 測っていないものを測ったように見せない | 総合点、明瞭さ、声の大きさの良し悪しを出さない。測れなければ「測れませんでした」と出す |
| 初めての人を止めない | 失敗の表示にも次の操作を置く。ログイン、登録、インストールを求めない |

## 2. 配色

地は明るくする。暗い配色は作らない。`<meta name="color-scheme" content="light">` を入れる。

| 名前 | 値 | 使う所 |
| --- | --- | --- |
| `--paper` | `#F6F2E9` | ページの地 |
| `--card` | `#FFFDF9` | カード、歌詞の面、朱の上の文字 |
| `--ink` | `#201D19` | 本文、線の強いボタン |
| `--ink-2` | `#4B453B` | 説明の文 |
| `--ink-3` | `#655D50` | 補足、標準の値 |
| `--rule` | `#D9D0BF` | カードの線、弱いボタンの線 |
| `--rule-2` | `#E7E0D2` | カードの中の区切り線 |
| `--track` | `#ECE6D8` | 帯の未到達の部分 |
| `--shu` | `#B23A1C` | 塗りのボタン、`>`、入口の一覧の「/練習モード」の名前、歌の中の読み上げた字（余韻の印の塗った所を含む）、録音の丸 |
| `--shu-deep` | `#9C3014` | 小さい朱の文字、注意の判定 |
| `--shu-soft` | `#FAEBE3` | 次に直す項目の行、直す点の表示 |
| `--seg-shimo` | `#B8DCB2` | 帯の下の句 |
| `--seg-yoin` | `#F6D56E` | 帯の余韻 |
| `--seg-ma` | `#F3B283` | 帯の間 |
| `--seg-kami` | `#A6C2EC` | 帯の上の句 |

- 歌の中の朱は、すでに読み上げた字だけに使う。伸ばす印、余韻の印、決まり字も、まだ読んでいないあいだは字と同じ `--ink` にする（2026-11-04 のユーザーの判断）。
- 帯の4色は区間にだけ使う。色だけで伝えず、必ず区間の名前を添える。
- 判定を赤と緑で塗らない。色を付ける行は、次に直す1点に選ばれた1行だけである。
- 朱は Claude の製品の色に寄せない。Anthropic のロゴと、公式の製品に見えるマークを使わない。

文字と地の組み合わせは、見本の値で計算してすべて 4.5:1 以上である。最も低いのは `--shu` と `--track` の 4.80:1 で、帯の面に朱の小さい文字を置かない。

## 3. 文字

歌だけをはんなり明朝で出し、ほかは端末の書体を使う。

| 名前 | 書体の並び | 使う所 |
| --- | --- | --- |
| `--f-uta` | `"yomimasu-uta", var(--f-serif)` | 歌（本文、ふりがな、伸ばす印、決まり字） |
| `--f-sans` | `"Hiragino Sans", "Hiragino Kaku Gothic ProN", "Noto Sans CJK JP", "Noto Sans JP", "Yu Gothic", system-ui, sans-serif` | 本文、ボタン |
| `--f-serif` | `"Hiragino Mincho ProN", "Noto Serif CJK JP", "Noto Serif JP", "Yu Mincho", serif` | 見出し、次に直す1点 |
| `--f-mono` | `ui-monospace, "SF Mono", Menlo, "Roboto Mono", monospace` | コマンド、数値 |

はんなり明朝の決まり：

- 歌に限る理由：歌の字は札の読みの表で閉じているので、使う字だけを切り出せて、ファイルが小さい。見出しや説明に広げると、文章を直すたびに切り出しを作り直すことになる。
- 規約は IPA Font License v1.0 である。切り出したものは派生フォントになるので、CSS の名前だけでなく、フォントの中の名前とファイル名も元と違うもの（`yomimasu-uta`）にする。`NOTICE.md` の行は IPA Font License として書く。置く前に規約の全文と照らす。
- 切り出す字は、札の読みの表の本文と仮名（序歌を含む）、ひらがな全体、`ー` とする。ふりがなを足しても切り出しを作り直さずに済む。
- 切り出したファイルは同じオリジンから配信する。外のフォント配信は使わない。
- フォントを置く PR で、規約の全文をフォントの隣に置き、`NOTICE.md` に元のフォントの名前、版、入手先、切り出し方を書く。切り出しの道具を依存に足すときは、理由を PR に書く。
- 太さは1つしかないので、歌は `font-weight: 400`、`font-synthesis: none` にする。合成した太字は線がつぶれる。
- 読む画面では、録音を始める前に `document.fonts.load` で読み込みを終える。録音中に書体が替わると歌詞の位置が動く。読み込めなければ `--f-serif` で出す。
- 見本はフォントを持たない。端末にはんなり明朝があれば `local()` で使い、なければ `--f-serif` で出す。

| 役割 | 大きさ | 行の高さ |
| --- | --- | --- |
| 本文 | 16px | 1.8 |
| カードの説明 | 15px | 1.7 |
| ボタン | 15px | 1.4 |
| 補足、標準の値 | 13px | 1.7 |
| コマンドの行 | 14px | 1.7 |
| 見出し | 24px、明朝 | 1.45 |
| 入口の題 | 30px、明朝 | 1.4 |
| 次に直す1点 | 22px、明朝 | 1.45 |
| 読む画面の歌 | `clamp(18px, min(6vw, 3.6svh), 26px)`、明朝 | 1.6 |

- 13px より小さい文字を使わない。例外は、帯の名前と秒数の 12.5px と、歌の枠の区切りの見出しの 12px（歌が縮んだときの下限）である。読む画面の歌は、枠に収めるために表の値より小さくなることがある（7節「大きさと寸法」）。
- 数値は `font-variant-numeric: tabular-nums` にする。動く数値の桁が揺れないようにするためである。

## 4. 余白と幅

- 1列の画面にする。幅は最大 `34rem` で中央に置く。パソコン用の別の形は作らない。
- 左右の余白は 16px、カードの内側は 12〜16px、ブロックの間は 16px にする。読む画面だけ 10px に詰める。
- 角の丸みは、ボタン 10px、カード 12px、入口の一覧 14px、帯 4px にする。
- 高さは `100svh` を基準にする。`100vh` はスマホのアドレスバーの分だけ切れるので使わない。
- 固定の位置に置く部品を作らない。`position: fixed` は使わない。例外は、入口の下端の「↓」だけである（8節「入口の絵と「↓」」）。試作の虫眼鏡も、開いているあいだ指の上に固定の位置で出す（8節「入口の絵の虫眼鏡（試作）」）。

保証する範囲：

| 幅×高さ | 例 | 条件 |
| --- | --- | --- |
| 360×560 以上 | 小さいスマホ | 横スクロールなし。録音の画面が1画面に収まる |
| 393×659 | iPhone 15 Pro の Safari の見える範囲（`100svh` の仮定） | 入口は先頭の項目と2番目の項目の上端まで、聞く画面は全体が1画面に収まる。入口の一覧の3番目から下と下端の行（Built with Claude Code.）はスクロールで出る（2026-11-06 のユーザーの判断。8節「入口の絵と「↓」」）。前は入口も一覧の最後の項目まで収めていた（2026-11-04） |
| 幅 320px | 古い小型機 | 横スクロールなし。縦のスクロールは許す |

## 5. ボタン

| 種類 | クラス（見本） | 見た目 | 使う所 |
| --- | --- | --- | --- |
| 塗り | `btn btn--fill` | 朱の塗り、太字 | その画面で一番押してほしい操作。1つだけ |
| 線 | `btn` | `--ink` の線 | 再生など、その場の操作 |
| 弱い線 | `btn btn--line` | `--rule` の線、地は透明 | 別の道へ進む操作 |

- 押せる所は高さ 44px 以上にする。通常のボタンは 48px である。
- 移動は `<a href>`、その場の操作は `<button>` にする。JS がなくても移動できるようにするためである。
- 塗りのボタンは、親指に近い下側に置く。
- 再生と停止の印は SVG にする。文字の ▶ は端末で形が変わることがある。
- 2択の切り替えは `aria-pressed` で表し、選んでいる方を太字と 2px の線にする。塗りのボタンより目立たせない。
- 無効のボタンは `disabled` にして、理由が分かる場所に置く。

## 6. カードと行

- カードは `--card` の面に `--rule` の線で、影を付けない。
- カードの中の項目は `--rule-2` の線で区切る。
- 優先度は「優先 高」「優先 中」「優先 低」の文字で出す。高だけを `--shu-deep` にする。
- 次に直す1点のカードだけ、線を `--ink` にする。

### たたんだ行（ポイントを知る）

項目が多い「ポイントを知る」（52項目）は、項目を見出しの1行にたたみ、押すと説明が開く形にする（2026-11-06 のユーザーの判断。見本で比べた案と経緯は `docs/decisions.md`）。

- 1行は `<details class="pt">` と `<summary>` で作る。JS がなくても開け閉めできる。画面を開いたときは、どの行も閉じておく。
- `<summary>` には、優先の札（`<span class="prio">`）と見出し（`<b>`）をこの順に入れる。札は見出しと同じ行の右に置き、読み上げの順は札、見出しのままにする。
- 開閉の印は文字の記号（▶ など）にせず、`--ink-3` の線で描いた山形にし、開いたら上を向ける。端末で形が変わらないようにするためである（5節の再生の印と同じ理由）。
- 押せる所の高さは 48px 以上にする。
- 開くと、説明と出典の印を出す。印は段落の終わりに `<span class="src">— …</span>` で小さく付け、印の途中で折り返さない（「教科書の出典」の節）。行の中に、さらに折りたたみ（「ん」の説明の `details.more`）を置いてよい。
- 行はテーマごとに1枚のカード（`card pts`）にまとめ、カードの上にテーマの見出し（`<h3 id="t-…">`）を置く。テーマは初めて読む人がつまずく順に並べる。テーマの中は高、中、低の順で、同じ優先の中は元の順にする。
- ページの見出しの下に、ページの役目を言う文と「見出しを押すと説明が開きます。」を置き、その下にテーマへ移る目次（`nav.card.toc`、2列、同じ画面の中のリンク）を置く。優先の断りは頭に置かず、ページの一番下の出典の1行の上に置く（2026-11-06 のユーザーの判断。読む前のノイズにしない）。目次の数は、組み立てのときにテーマの下の行から数える（`site/point.ts`）。手で書かない。
- hash の先がたたんだ行の中にあるとき（1首のページから `/point/#yoin-n` へ移ったときなど）は、先を含む行と折りたたみを開いてから移る（`site/client/ui/shell.ts` の `showTarget`）。
- 色は足さない。

## 7. 帯と歌の枠

### 帯

- 帯は B1（総論）と、まず1回読む の導入の段1で使う。帯の部品は1つにする（見本の `buildBand` と `paintBand`）。お手本を聞く画面と読む画面の歌の枠には出さない（下の節。2026-11-04 のユーザーの判断）。
- 区間は配列で持ち、数を4に固定しない。序歌は下の句を2回読むので、形が変わる。
- 区間の幅は秒数に比例させる。
- 帯は1本にする。帯の中の文字は2行で、1行目に区間の名前、2行目に標準の秒数を「5秒」のように単位を付けて置く。左から 5秒、3秒、1秒、6秒 と並び、5・3・1・6 の方式がそのまま読める。図の中の数字には単位を付ける（2026-11-04 のユーザーの判断）。
  - 「秒」は 0.72em にする。「間」の区間は幅 320 で約 18px しかなく、数字と同じ大きさの「1秒」は切れる。前は同じ理由で単位を付けなかった。
  - 帯の文字の規則は、区間の直下の span（`.seg > span`）にだけ当てる。中の「秒」の span まで絶対配置にすると、iOS の Safari で「秒」が名前の上に重なった（2026-11-04 にシミュレーターで確認）。
- 帯の要素に `aria-label` を付け、「下の句 5秒、余韻 3秒、間 1秒、上の句 6秒」のように単位まで読ませる。
- 今の区間には 2px の線を付ける。進んだ分は区間の色で左から埋める。今の線は、余韻と間の区間のあいだ両方に付ける。
- 時間は標準の 5・3・1・6 で進める。お手本の音とはずれてよい。
- 総論（B1）の帯の下のボタンは「実際の読みで確認する」にする。押すと、お手本のうち 5・3・1・6 に最も近い1組を、帯と一緒に再生する。帯だけを動かすボタンは置かない（2026-11-03 のユーザーのコメント）。
  - 下の句と上の句は別の札から選んでよい。間は再生のときに 1.0 秒にする。
  - 下の句は、最後の音の始まりと声の終わりが、標準の 5 秒と 8 秒に最も近いものを選ぶ。上の句は、長さが 6 秒に最も近いものを選ぶ。区切りは自動の測定で、人が付けた正解ではない。
  - 今の候補は 81番の下の句と 45番の上の句である。区切りの値は読手の確認までリポジトリに入れないので、ここには札の番号だけを書く。

```ts
type Segment = { key: 'shimo' | 'yoin' | 'ma' | 'kami'; name: string; sec: number; label: string };
```

`label` は「下の句（5秒程度）」「余韻（3.0秒）」「間（1.0秒）」「上の句（6秒程度）」である。歌の枠では、余韻と間を1つの区切りとして扱う（見本の `PHASES`）。

### 歌の枠（お手本を聞く画面と読む画面）

お手本を聞く画面と読む画面は、同じ歌の枠を使う。枠の中に置くのは歌だけで、時間とともに変わるのは、字の朱の塗りと今の区切りの囲みだけにする（2026-11-04 のユーザーの判断）。上の帯、枠の地の減り、区間の名前と残り秒数、秒数の札、ゲージ、タップの札は出さない。

- 経緯：
  - 見本を触ってもらった初心者から、次のフィードバックを受けた。読む間は朱の字を追うので精一杯で、上の帯は視界に入らず、右上の秒数は見る余裕がない。地の減りは字と違う速さで動くので、ノイズに感じる。
  - 見本で、秒数を歌のそばに出す案を3つ比べた（余韻の印の下、上の句の頭、2つの句のあいだのゲージ）。そのうえでユーザーが、目線を朱の字に集めるために「ゲージを全部なくす」を試して決めた。
  - お手本を聞く画面も同じ形にした。帯と地の減りを説明する導入の段をなくしたので、聞く画面にだけ残すと説明のない部品になるからである。
- 字が朱になっていくのはカラオケと同じ理屈なので、たいていの人は、説明がなくても字に合わせて読める（ユーザーの判断）。余韻の入りを合わせる操作を置かないのも、同じ理由による（9節）。

#### 区切り

- 歌を3つの区切りに分け、右から 下の句、余韻と間、上の句 の順に並べる。区切りごとに、上に見出し、下に本文を置く。見出しも本文も縦書きにする。読み札が縦書きだからである（ユーザーの判断）。
- 見出しは「下の句5秒」「余韻3秒」と「間1秒」の2列、「上の句6秒」にする。数字は縦中横（`text-combine-upright`）にする。書体は `--f-sans` の太字、色は `--ink-3`、大きさは歌の 0.62 倍とし、12px より小さくしない。
- 見出しの高さは、いちばん長い「下の句5秒」に合わせてそろえる。どの区切りも、本文が同じ高さから始まるようにするためである。
- 余韻と間は1つの区切りにする。間を別の区切りにすると、1秒だけの区切りに囲みが移って跳ね、せわしない（ユーザーの指摘）。区間名を「余韻と間」の1つにした判断（2026-11-03）と同じ理由である。見出しは「余韻3秒・間1秒」の1列にしていたが、2列にした（ユーザーの判断）。
- 余韻と間の区切りの本文は、下の句の最後の字と余韻の印を1列に置く。間の1秒に当たる字は置かない（下の「朱の塗り」の節）。最後の字を余韻の区切りに置くのは、余韻の3秒が最後の音そのものを含むからである（5-3-1-6 の余韻の数え方。根拠の資料は非公開の記録にある）。
- 区切りの高さは、いちばん長い区切りにそろえる。囲みが区切りごとに伸び縮みしないようにするためである。

#### 囲み

- 読んでいるあいだ（t > 0）、補助ありのとき、今の区切りを `--ink` の 2px の線で囲む。下の句は 0〜5秒、余韻と間は 5〜9秒、上の句は 9秒からである。囲みが移るのは、読み始め、5秒、9秒の3回になる。
- 待機（t = 0）では囲まない。まだどこも読んでいないからである。
- 線を朱にしないのは、朱を読み上げた字だけに使うからである。帯の今の区間の線と同じ黒にする。
- 囲みの線の分の内側（0.35em、左右 0.3em）は、囲まないあいだも取っておく。囲みが出ても歌が動かないようにするためである。

#### 朱の塗り

- 朱は、歌の中では「すでに読み上げた字」だけに使う（ユーザーの判断）。伸ばす印、余韻の印、決まり字は、まだ読んでいないあいだは字と同じ `--ink` にする。1首のページの歌の中も同じにする。
- 字は、その字の始まりから次の字の始まりまでに、上から少しずつ朱にする（カラオケと同じ塗り方。ユーザーの判断）。伸ばす印も、どれだけ伸ばすかが塗りで分かる。見本は、字ごとの `--p` と `background-clip: text` の `linear-gradient` で塗り、毎フレーム変わった字だけを書き換える。
- 下の句の最後の字は、余韻の始まり（5.0秒）から1拍分で塗る。続けて余韻の印を、字の終わりから余韻の終わり（8.0秒）まで、一定の速さで上から塗る。
- 間の1秒（8.0〜9.0秒）は、何も塗らない。囲みは余韻と間の区切りにかかったままである。
  - 経緯：余韻の印のあとに「（間）」と書き、間の1秒で塗る形を試した（2026-11-04 夜）。字ごとに一気に朱にすると最後の字が 8.67秒で終わり、上の句の頭まで何も動かない時間ができたので、いったん1秒で滑らかに塗る形にした。そのあとユーザーが何回か試し、「（間）」があるとかえって読みづらいと判断して消した（同日夜）。
- 上の句の最初の字は 9.0秒から塗る。
- 時刻の正確さは、画面を描く間隔（1/60秒ほど）の範囲である。

#### 字の時刻（C3）

- 字の時刻は、札の読みの表から、拍と伸ばしの重みで割り振る（2026-11-04 のユーザーの判断）。
  - 重みは、発音の拍の数にする。ふりがなのある字は読みの拍の数、ない仮名は 1 である。拗音の小さい字（ゃ、ゅ、ょ など）は前の字と合わせて1拍にする。伸ばす印「ー」は 2 にする。
  - 下の句は、最後の拍を除いて 0〜5秒に、句の全体で割り振る。行の分かれ目は時刻に関わらない。
  - 最後の拍は 5.0秒から始め、1拍分で塗る（上の節）。
  - 時刻はいつも拍で作る。下の句が漢字で終わる札（2番の「山」、29番の「花」など11枚）の漢字の表記では、最後の漢字を余韻と間の区切りに置き、その漢字は自分の拍の範囲で塗る。「花」なら「は」の始まりから「な」の終わりまでで、5.0秒より少し前から塗り始める。かなと漢字の表記で、同じ拍は同じ時刻になる（2026-11-04 のユーザーの判断）。
  - かなの表記は、読みが2拍以上の字を1拍ずつに分ける。拗音は小さい字ごとに分けない。「ちょう」の「ち」と「ょ」が別の拍のように進むからである。
  - 上の句は 9〜15秒に割り振る。
- 字数で等分しない。要件 C3 の「字数で等分すると誤った手本になるので使わない」に当たるからである。
- 時刻は標準の 5・3・1・6 で、お手本の音とはずれてよい。読手の測定値は使わない。お手本を聞く画面で字を音に合わせて進めるのは、読手の確認が取れてからにする（要件の未決の判断）。
- 見本の `LYRICS` は、行ごとに手で時刻を置いた仮の値である。アプリは上の割り振りで作る。

#### 余韻の印

- 形は、上から下へ細くなる三角（▼を縦に伸ばした形）にする。余韻に入ったら早めに弱め始める「にんじん型」を理想とする資料（講習資料 s.25。スキルの `references/timing.md`）に合わせる（2026-11-04 夜のユーザーの判断）。
- 経緯：同じ日の夜に、上を四角（声を保つ所）、下を三角（弱め始めてよい最後の1秒、`FADE_SEC = 1`）にした五角形を試した。全部が三角だと「余韻の始めから弱める」と誤解される、というユーザーの指摘による。そのあとコードのレビューで、五角形は音量を保つ「だいこん型」に近く読め、資料が避ける形と食い違うと指摘された。ユーザーの判断で三角に戻した。
- 塗りは、下の句の最後の字を塗り終えてから余韻の終わり（8.0秒）まで、一定の速さにする。

#### 補助を外したとき

- 塗りも囲みも出さない。歌は全部 `--ink` のままにする。枠の上の端に「補助なし」と出す（9節）。

#### 大きさと寸法

- 歌は枠に合わせて縮める（見本の `fitLyric`）。収まるまで最大4回測り直す。見出しは 12px より小さくしないので、歌と同じ割合では縮まない。1回で縮めきろうとした版では、iPhone 13 mini で見出しが枠の上で切れた（2026-11-04 のユーザーの報告）。

  - 左だけに取ると、歌が右に寄って余白が偏った（ユーザーの指摘）。

  - 375×600 で 16.2px、360×640 で 14.9px。

### 100首の一覧（1首ずつ学ぶ）

番号が100個並ぶだけでは、どこから見ればよいか分からない（2026-11-03 のユーザーのコメント）。そのため決まり字を主に出し、並べ方を2つ持つ。

- 並べ方は「決まり字順」と「歌番号順」の2つで、最初は決まり字順にする（2026-11-03 のユーザーのコメント）。決まり字順は、決まり字の最初の音で分け、その音で始まる札の数で並べる。分けるのは発音の音で、44番「あふこ」と26番「をぐ」は「お」に入る。
- 決まり字順には向きが2つある。「多い→少ない」（最初の向き）は読手テキストの読み方一覧（完全版、令和2年4月1日初版 p.5-15。抜粋版の令和7年4月1日改訂版と印刷の差はない）と同じ並びで、あ 16首、な 8首、お・わ 7首 … う・つ・し・も・ゆ 2首、む・す・め・ふ・さ・ほ・せ 1首の順になる。「少ない→多い」はその逆で、むすめふさほせから始まり、あで終わる。札の数が同じ音どうしは、どちらの向きでも一覧の順にする（「少ない→多い」でも むすめふさほせ、うつしもゆ、いちひき の順）。
- 向きのボタンは、決まり字順のときだけ並べ方のボタンの下に出す。
- 1首しかない音（む・す・め・ふ・さ・ほ・せ）も、ほかの音と同じく音ごとに見出しを立て、むすめふさほせの順に並べる。いったん「1枚札」の見出し1つにまとめたが、ユーザーの判断で音ごとに戻した（2026-11-03）。
- 音の見出しには音と首数を出す。見出しの音は歌の書体で `--shu-deep` にする。
- 音の中は決まり字の仮名の順にする。一覧の音の順は札の読みの表のページで確かめたが、音の中の順は一覧と照らしていない。
- 切り替えはどれも2つのボタンの組で、押している方に `aria-pressed="true"` を付ける。
- 1札のマスは決まり字だけを出す。歌番号は「歌番号順」のときだけ、決まり字の上に小さく添える（並びの手がかりになるからである）。決まり字は札の読みの表の仮名の形（歴史的仮名遣い）にする。1行に3マス置く。決まり字は最長6字で、360px の幅でも1行に入る。
- 序歌はどちらの順でも先頭に置く。

### 1首のページ

上から、歌の枠、歌の印、お手本を再生のボタン、気をつける点、余韻で伸ばす音の口の形、言葉の助言、出典の1行の順に置く。その札だけの点を読ませるため、全部かほとんどの札に出る点と、当たる札で同じ文になる点は並べない（2026-11-06 のユーザーの判断。理由と数は `docs/decisions.md`）。

- 気をつける点に出さないもの：余韻で伸ばす音、四句の途中の伸ばし、鼻濁音、句切れと掛詞、字余り、2020年の改訂。カードのすぐ下に、どの札でも「全部の札に共通の点（余韻、四句の伸ばし、鼻濁音、仮名の読み方の決まりなど）はポイントを知るにあります。」の1行を置く。
- 余韻で伸ばす音は、口の形の図の見出しに出す（「余韻で伸ばす音「る」の口の形」）。
- ふりがなで見える読み替え（ハ行、「む」、「ゐ」「ゑ」「ぢ」「づ」、長音）は残す（ユーザーの判断）。
- その4項目は、決まりの一般論（「語の頭にないハ行の音は…」など）を書かず、その歌の箇所だけを書く（「「川（がは）」の「は」は「わ」…と読みます。」）。見出し、優先、出典の印は変えない（2026-11-06 のユーザーの判断）。
- 歌の枠のすぐ下（お手本のボタンの前）に、歌の印「伸ばす箇所 抜粋版 p.7、ふりがな・注・余韻の印 冊子 p.7」を1行置く。ページは札の読みの表の `origin.stretches.page` と `origin.notation.page` から出し、記録のない部分は出さない。序歌も同じである。
- 出だしが同じ札は、項目にせず、カードの最初の行に「出だしが同じ札：なげけ」の1行だけを出す。優先の印と出典の印は付けない。
- 無声化は、箇所と「無理に避けず、自然に読みます」だけを書く。
- 優先の断り（「優先の高・中・低は…」）は、優先の印のある項目があるときだけ出す。項目も出だしが同じ札もない札では、カードを出さず、ポイントを知るへの1行だけにする（今はどの札にも項目がある）。
- 言葉の助言は、同じページの項目と同じことを言う行を出さない（大山札、初句6字、81番の1字決まり、読手のメモの長音の一覧など）。行はスキルの表に残し、どの行を出さないかは `site/karuta.ts` の `hideRepeats` が決める。表の行が変わって当たらなくなったら、組み立てが止まる。
- 口の形の図の下の説明は1行にする（「図は、一般の音声学の資料（Wikipedia ほか）をもとにこのアプリが描いたスケッチで、寸法は測っていません。」と、朱の点か「ん」の朱の帯の説明）。資料の名前は書かず、「このアプリについて」の `#src-phonetics` と `#src-research` へリンクする。パネルの保つ所は「保つ（このアプリの解釈）：」にする。「ポイントを知る」の6つの図の説明は、この節では決めない。
- 出典は「教科書の出典」（13節）の形にする。項目と助言の出典は、段落の終わりの短い印（`<span class="src">— 冊子 p.23</span>`、`— 読手メモより`）にし、別の行にしない。別の行に置くのは歌の印だけである。ページの終わりは出典の1行だけにする。
- お手本：歌の枠と歌の印のすぐ下に、線のボタン（`btn`）を1つだけ置く。SVG の再生の印と「お手本を再生」で、押すとその札の上の句（`NNN_1.m4a`）を鳴らし、1秒あけて下の句（`NNN_2.m4a`）を鳴らす（約15秒）。序歌も同じボタン1つで、上の句と1回目の下の句（`000_1.m4a`）、1秒、2回目の下の句（`000_2.m4a`）の順に鳴る。2026-11-06 のユーザーの判断で、上の句と下の句を分けた2つのボタンや、通しと合わせた3つのボタンは置かない。
  - 鳴っているあいだはボタンを停止の印と「やめる」にし、押すと止める。鳴り終えたら戻す。別の画面へ移ったときと、ページを離れたとき（`pagehide`）にも止める。
  - 歌の字は朱で塗らない。1首のページの歌は止まった表示で、字の時刻（標準の 5・3・1・6）はお手本の音と合わないからである。
  - 読み込めないときは、ボタンの下に11節の「お手本を読み込めませんでした。…」を出し、次に押したら消す。
  - JS がないときはボタンを隠す（100首の一覧の並べ方のボタンと同じく、HTML では `hidden` にしておき、部品が動いたら出す）。
  - 押した時点で鳴らし始め、同時に入力の行へ `お手本を再生` を打ち込む（8節「押したらターミナルに出す」）。「やめる」は打ち込まない。

## 8. コマンド風の入口

### 画面の形

読む流れ（聞く、読む）と、入れる先を尋ねる画面を除いて、どの内容も同じ順に並べる。読む流れは1画面に収めるので、5 と 6 がなく、歌の下にボタンを置く。入れる先を尋ねる画面は、問いと選択肢が 5 と 6 の代わりになる（「AI に入れる」の節）。

1. 上の帯：左に `/yomimasu`（入口へのリンク）、右に進み具合（`1 / 3 聞く` など）
2. 実行の行：`> /yomimasu 総論を学ぶ`
3. 読んだ行：`● Read 総論.md`
4. 本文。図解、音声、録音はカードで出す
5. 入力の行：`> /yomimasu ▮`
6. 「次は？」と次の操作

入口には 2 と 3 がなく、本文の代わりに題を置き、題と 5 のあいだに絵を置き（「入口の絵と「↓」」の節）、5 の下に一覧を置く。一覧の先頭だけを朱の地にして、「はじめての人はここから」を添える。6番目の「/練習モード」は、名前の字（`/練習モード`）だけを朱（`--shu`）にして目立たせる。地は塗らず、字の太さと添え書きはほかの行と同じにする。初めて触る人は「/まず1回読む」を、読みの練習ができると聞いて来た人は「/練習モード」を押すからである（2026-11-06 のユーザーの判断）。朱の地は朱が2か所になって気が散り、太字も微妙だったので、見本で見比べてこの形にした（2026-11-07 のユーザーの判断。`docs/decisions.md`）。名前の字の朱は塗りではないので、1節の「塗りのボタンは1画面に1つ」には数えない。字の大きさと行の高さはほかの行と同じ（15px、48px）なので、最初の画面に入る範囲（「入口の絵と「↓」」の節）は変わらない。一覧は7項目で、最後は「/インストール」である（「AI に入れる」の節）。自由入力の欄は作らない。

一覧のコマンド名（`/総論を学ぶ` など）は折り返さない（`white-space: nowrap`）。狭い画面では、添え書きの側を折り返す。iPhone 13 mini（幅375px）で「/つまずきどころ」が2行に折れていた（友人のフィードバック、2026-11-03）。

入れ替えると前の出力は消える。Claude Code のように積み重ねない。戻る操作で前の内容に戻すためである。

### 入口の絵と「↓」

試作の版（次の節「入口の絵の虫眼鏡（試作）」）では、この節の升目の式と升目を写す画素を、次の節の決まりで置き換える。字は、#41 の版と同じく升目ごとに `fillText` で描く。試作を採るときは、この節を書き直す。

入口の題の下に、決まり字で組んだ読手の絵を動かして置く。このアプリが読みのアプリであることを、最初の画面で見せるためである（2026-11-06 のユーザーの判断。Issue #41）。置き方は、誘導しない形で Fable 5.1 に相談したおすすめ案で、「↓」はユーザーの案である。

置き方：

- 上から、題、題の下の文、絵、`> /yomimasu`、一覧の順に並べる。題、絵、入力の行のあいだは詰め、題の上下の余白を 12/8px にする（前は 20/16px）。
- 絵の高さは `max(160, min(520, 画面の高さ − 先頭の項目の下端 − 24))` px にする。先頭の項目の下端は、絵の高さを除いて測る。画面の高さは `100svh` で、iOS の Safari でアドレスバーが縮んでも絵の高さを変えない。
  - 最初の画面に、朱の先頭の項目と、2番目の項目の上端 24px までが入る。
  - 上限の 520px は、パソコンなど縦に長い画面で、絵だけが大きくならないためである。
- 升目は `clamp(floor(絵の高さ / 32), 8, 11)` px にする。一覧の文字と行の高さは変えない。
- JS がないときは、絵の場所が空いたまま残る。JS が測る前に場所を取っておかないと、読み込んだあとで一覧が下へ跳ねるからである。

Playwright の Chromium で測った値（2026-11-06）：

| --- | --- | --- | --- | --- | --- |
| 393×659 | 315px | 9px | 40×35 | 635px | 923px |
| 360×640 | 296px | 9px | 36×32 | 616px | 913px |
| 375×812 | 468px | 11px | 31×42 | 788px | 1085px |
| 448×940 | 520px | 11px | 37×47 | 840px | 1128px |

動かし方：

- `YomimasuKv.mount(要素, { stream, cell, fps: 20, layout: 'tate', tapGyro: false })` で動かす（`site/client/kv.ts`）。`tapGyro: false` で、iOS で絵をたたいても傾きの許可を求めない（「初めての人を止めない」）。許可の要らない端末（`DeviceOrientationEvent.requestPermission` がない端末）では、傾けると回る。Playwright の Chromium にはこの関数があり、入口では傾きを受けなかった。Pixel の Chrome で傾けて回るかは確かめていない。横になぞると回り、縦のなぞりはページのスクロールに残す。
- 3周（36秒）で `set({ playing: false, time: YomimasuKv.READ_T })` にして、読む場面で止める。絵に触ると動き出し、また 36 秒で止まる。止めたあとは、時刻が変わらず向きも 1.5 度より動かないあいだは描き直さない。
- コマンドを打ち込むあいだ（入力の行に `is-sent` が付いてから入れ替わるまで）は止める。入口へ入れ替えて冒頭の文を流すあいだ（絵に `is-held` が付いているあいだ）は、動かし始めない。殻（`shell.ts`）は変えず、この2つの印を見る。
- 画面の外へスクロールしたあいだは描かない。
- WebGL2 がない端末では、読む場面で止めた1コマを、シェーダーと同じ式で CPU で写して出す。枠の高さは変えない。2026-11-06 に Mac の Playwright の Chromium で比べると、WebGL2 で描いた止めた1コマと同じ画素になった（e2e は、端末による誤差を見込んで、違う画素が2%未満であることを確かめる）。Mac（M5）の Chromium で CPU を4倍遅くすると、開いてから描き終えるまで 1.0〜1.3 秒かかり、そのあいだ画面は止まる。
- `prefers-reduced-motion: reduce` では、動かす版を作らず、読む場面で止めた1コマを出す。傾けても、触っても動かない。
- 外へ通信しない。スクリプトと決まり字の列は、入口を開いたときに読み込む1つのファイルに入っている（約 32 KB、gzip で約 13 KB）。

決まり字の列：

- 札の読みの表から、組み立てのたびに作る（`site/kimariji-stream.ts`）。札を読む順を乱数で決め、読まれた時点で、まだ読まれていない札と音で区別できる最短の頭を、読まれた順に並べる。字は札の仮名で出す。試合が進むほど決まり字は短くなる。
- 1試合では升目が埋まらないので、乱数の種を 1 から 12 まで変えた12試合を続ける（2568字）。読む順は Python の `random.Random(種).shuffle` と同じにして、見本の絵と同じ字の並びにした。

「↓」：

- 一覧の最後の項目が最初の画面からはみ出すときだけ、画面の下端の中央に固定で出す。上の4つの画面では、どれも出る。
- スクロールが始まったら消し、上へ戻っても出し直さない。入口を開き直したときは、また判断する。
- 押せない印にする（`aria-hidden="true"`、`pointer-events: none`）。
- 1.4秒で 4px 浮いて沈む往復を続け、消えたら止める。`prefers-reduced-motion: reduce` では往復させない。

### 入口の絵の虫眼鏡（試作）

ユーザーの案（2026-11-06）で、升目を細かくし、長押しの虫眼鏡で決まり字を読ませる試作を、#41 の版と並べて作った。この版は、虫眼鏡を開く前も升目ごとに字を描く（2026-11-06 15時台のユーザーの案「#59 で拡大前もひらがなにした Ver がほしい」）。開く前は字の濃さの印で描く版（PR #59）とも並べ、夜にユーザーが実機で見比べて、どれを使うかを決める。採らなければ、この節を消す。

升目：

- 段の数を #41 の版の約2倍にして、机や読唱箱の形が出るようにする。升目は `clamp(round(絵の高さ / 64), 4, 6)` px で、393×659 と 360×640 で 5px、375×812 と 448×940 で 6px になる（段は #41 の版の 1.8〜1.9倍）。
- 升目1つを 2×2 の画素で写す（#41 の版は 3×3）。3×3 のままでは、写す画素が升目の数に比例して増え、1コマが重い。
- この大きさでは字は読めないが、#41 の版と同じく、升目ごとに決まり字と記号を `fillText` で描く。明るさから字の濃さと、記号（「・」「ー」「＋」）に落とす所を決める式も、#41 の版と同じである。虫眼鏡を開く前から、絵が仮名でできていることを見せるためである。字は虫眼鏡で読ませる。
- 升目が 8px 未満のときに、字の代わりに濃さの印（「・」は小さい点、「ー」は横線、「＋」は十字、字は四角）を置く版（PR #59）は、1コマが軽いが、開く前は仮名に見えない（下の表）。
- 字を1回だけ並べて描いた帯（atlas）から `drawImage` で写す案は、Chromium で `fillText` より重かったので採らなかった（下の表）。
- 4px にしないのは、1コマが重くなるわりに、机と箱の形の見え方が変わらなかったからである（下の表。印で描く版で測った）。

1コマを描く時間（2026-11-06。Mac（M5）の Playwright の Chromium、GPU は Metal、CPU を4倍遅くした（CDP の `Emulation.setCPUThrottlingRate`）。動きを止めて時刻を変えながら60コマ続けて描いた平均の、3回の中央値）。左の値は JS の処理と WebGL の写しで、右の値は毎コマ Canvas の画素を読み戻して、字を描き終えるまでを含む：

- atlas は、GPU で描く Canvas で毎コマ読み戻すと、Canvas が GPU から外れて1コマ 1 秒を超えた。アプリは絵の Canvas を読み戻さないが、端末によって起こりうるので採らなかった。
- Pixel 8 Pro と思われる端末では、46×61 の升目（3×3）で1コマ 23.3 ms だった（Issue #41 の「参考」）。試作の 448×940 は 69×86 の升目を 2×2 で写すので、写す画素の数はその 0.94 倍である。描く字の数は約2倍になる。
- 字の版は、印の版より1コマが 393×659 で約 1.3 倍、448×940 で約 1.4 倍重い。

虫眼鏡：

- 絵を 350ms、8px 以上動かさずに押すと開く。マウスは押したままで同じに動く。
- 押してから 350ms 未満に 8px 以上動いていたら、開いたあとにその動きが届いても、長押しではなかったとして閉じる。指の動きは描画のコマに合わせて届くので、コマが遅れると開くタイマーより遅れて届く。届いた時刻ではなく、動いた時刻（`timeStamp`）で比べる。
- 円（直径 176px）の中に、指の下の升目の字を、升目 18px（字は約 17px）で、絵と同じ墨の色で描く。淡い升目の字も読めるよう、濃さの下限を 0.4 にした。
- 円は指の上（中心が 116px 上）にずらして出し、画面の中に収める。押したまま動かすと付いてくる。離すと閉じる。
- 開いているあいだは絵を止め、閉じたら開く前の状態に戻す。開いているあいだは、傾き、2本目の指、なぞりでも絵を回さない。絵に触った時点で止めた絵は動き出す（「入口の絵と「↓」」の節）ので、閉じると動く。
- 開いているあいだは、指を動かしてもスクロールさせない（`touchmove` を止める）。開く前の縦のなぞりは、ページのスクロールに任せる。
- iOS の長押しのメニューと文字の選択を切る（`-webkit-touch-callout: none`、`user-select: none`）。Android の長押しのメニューは `contextmenu` を止めて出さない。
- 動きを減らす設定と、WebGL2 がない端末の止めた絵でも使える。

回すか虫眼鏡を開くか：

- 押してから 350ms 未満に 8px 以上動かすと、なぞりとして絵を回し、虫眼鏡は開かない。指では横の動きで回し、縦の動きはページのスクロールに残す（`touch-action: pan-y`）。マウスでは、押したまま動かすと横にも縦にも回る。
- 350ms、8px 以上動かさずに押し続けると、虫眼鏡を開く。開いたあとは、動かしても絵は回らず、虫眼鏡が付いてくる。
- 回す処理は #41 の版のスワイプ（`kv-live.js`）で、入口でもすでに効いていた。e2e で、マウスと1本の指の横のなぞりで回ることを確かめた。この版で回す処理は足していない。

操作の説明：

- 絵の枠の右上に、体言止めの2行「長押しで拡大」「ドラッグで回転」を、小さく（12px）、淡い墨（`--ink-3`）で重ねる。地は敷かない。文はユーザーの案のまま（2026-11-06 16時台。「体言止めで簡潔な説明でよいと思った」）。
- 虫眼鏡を使ったあとも消さず、出したままにする。2回目に来た人が、虫眼鏡と回し方を思い出せるようにするためである。端末には何も覚えない。
- 止めた絵（動きを減らす設定、WebGL2 がない端末）は回せないので、「長押しで拡大」だけを出す。
- 読み上げで操作が分かるよう、`aria-hidden` にしない。押せない文なので、指は下の絵に通す（`pointer-events: none`）。
- 4つの大きさのどれでも、回していない絵の1周のどのコマでも、説明の枠に字の升目が重ならない（e2e で確かめる）。回した向きによっては重なりうる。
- 絵の枠に重ねるので、入口の行の高さと4つの大きさの決まりは変わらない。

### 戻る

上の帯の `/yomimasu` だけでは、押すと戻れることが伝わりにくかった。そのため入口以外のどの画面にも、主の操作（塗りのボタン）の右に、幅の狭い線のボタン「戻る」を置く（2026-11-03 のユーザーのコメント）。幅は 76px で、主の操作と同じ行に並べる。主の操作がない画面（100首の一覧）では、「戻る」だけを右に寄せて置く。

押したときは、Claude Code で AskUserQuestion が出るときと同じ順に動かす（2026-11-03 のユーザーの指示）。

1. ターミナルに `/yomimasu 戻る` と打ち込む（「押したらターミナルに出す」の節）。
2. 打ち込んだ行の下に、質問「? どこに戻りますか？」を出す。質問の文を流し、選択肢はまとめて出す（「冒頭の文を流して出す」の節）。
3. 主のボタン群（「次は？」とその操作、聞く・読む画面の操作）を隠し、質問の選択肢と入れ替える。打ち込んだ行は残す。
4. 選択肢を選ぶと、その答えを「❯ 1つ前のページ（総論.md）」のように質問の下に出し、ひと呼吸（370ms）置いてから移る。

| 選択肢 | 移り先 |
| --- | --- |
| 1. 1つ前のページ（総論.md など） | 前の画面。かっこの中は前の画面の読んだ行の名前で、ない画面ではコマンドの名前にする。前の画面が入口のとき、前の画面がない（URL を直接開いた）ときは出さない |
| 2. トップページ | 入口 |
| キャンセル | どこにも移らない。打ち込まずにすぐ選択肢を閉じ、主のボタン群と空の入力の行に戻し、「戻る」に焦点を戻す |

- 行き先が入口しかないとき（入口から開いた画面、URL を直接開いた画面）は、質問を出さない。`/yomimasu 戻る` を打ち込み、ひと呼吸置いてから入口へ移る（2026-11-03 のユーザーの案）。選択肢が1つの質問は手間になるだけだからである。
  - 誤って押したときの備え：入口から1つ目の画面は教科書と練習の入口で、まだ何も入力していないので、戻っても失うものがない。一覧から1回で開き直せる。入口へは履歴を戻って移るので、ブラウザーの進む操作でも元の画面に戻れる。主の操作と「戻る」の間は 12px 空ける。
  - 録音したあとの画面（結果）は入口から1つ目ではないので、いつも質問を出す。
- 選択肢を出したら、最初の選択肢に焦点を移す。
- 移った先の画面は、ボタンを押して開いたときと同じく、実行の行、読んだ行、本文の順に出す。
- ブラウザーの戻る操作では、これまでどおり動きを出さない。
- 録音中は「戻る」を出さない。「やめる」で止める。
- 打ち込む文字は、ほかのコマンドに合わせて日本語の `戻る` にした。
- 経緯：上の帯の左を「‹ /yomimasu」、続いて「‹ 戻る」にし、「次は？」に「入口へ戻る」を足して外し、行き先をその場に重ねて出す形を経て、この形にした（同日、ユーザーの判断）。上の帯は `/yomimasu` に戻した。

### 押したらターミナルに出す

UX を Claude Code に合わせるため、ボタンやリンクなど押せるものは、どれも先にターミナルへ打ち込み、ひと呼吸置いてから動かす（2026-11-03 のユーザーの指示）。最初の体験（`/yomimasu まず1回読む`）と、ほかの操作の手触りをそろえるためである。

- 打ち込む先は、入力の行（`> /yomimasu ▮`）がある画面ではその行、ない画面（聞く、読む、100首の一覧、練習モード、入れる先を尋ねる画面）では上の実行の行である。
- 時間は「押したあとの動き」と同じで、280ms で打ち込み、90ms 置いてから動く。
- 打ち込まずにすぐ動くのは、止める操作（再生と録音の「やめる」、質問の「キャンセル」）だけである。読む画面の余韻のタップは、2026-11-04 になくした（9節）。
- 例外として、`<details>` の開け閉め（「ポイントを知る」のたたんだ行と「ん」の説明）と、同じ画面の中のリンク（「ポイントを知る」の目次）は打ち込まない。画面を入れ替えずにその場で開くか移るだけの操作で、それまでの「ん」の説明の折りたたみと同じ扱いにした（2026-11-06 のユーザーの判断）。殻は `<summary>` の押下を横取りしない。同じ画面の中のリンクは殻が受け、履歴を積まずに（`history.replaceState`）移る。ブラウザーに任せると state のない履歴が積まれ、そのあとの「戻る」が前の画面を見失うからである（`site/client/ui/shell.ts`）。JS がないときはブラウザーが移す。
- 質問の選択肢（「戻る」の行き先、入れる先）は、打ち込む代わりに、選んだ答えを質問の下に出してから動く。
- AI に入れる手順の「yomimasu.zip を保存」と「コピー」は打ち込むが、保存とクリップボードへの書き込みは押した時点で始める（「AI に入れる」の節）。
- 1首のページの「お手本を再生」も、押した時点で鳴らし始め、同時に打ち込み、打ち込み終えたら入力の行を空に戻す。遅らせて鳴らすと、iOS の Safari が利用者の操作として扱わないからである。ボタンに `data-echo` を付けると、殻（`site/client/ui/shell.ts`）がキャプチャの段でボタンの文字を読んで打ち込む。部品は鳴っているあいだ `data-echo` を外すので、「やめる」は打ち込まれない。殻が打ち込んでいるあいだにまた押されたら、打ち込まずに部品だけが動く。ほかの画面の中のボタン（聞く画面のお手本を聞く、並べ方の切り替えなど）は、まだこの入口につないでいない（2026-11-06）。
- 画面が変わらない操作（再生、補助の切り替え、並べ方の切り替え）は、動いたあとに入力の行を空に戻す。実行の行は、最後に打ち込んだコマンドを残す。
- 利用者が押していない動き（25秒の時間切れで録音を終える、など）は打ち込まない。
- 打ち込む文字は「コマンドの対応」の表に従う。表にないボタンは、ボタンの文字をそのまま打ち込む。

### 押したあとの動き

| 時刻 | 動き |
| --- | --- |
| 0ms | 押す。HTML の取得を始める。ほかのボタンを薄くする |
| 0〜280ms | 入力の行に文字を足す。字数によらず合計 280ms にする |
| 370ms まで | そのまま置く |
| 370ms | 本文を入れ替え、一番上へ移る。実行の行を出す |
| 480ms | `● Read` の行を出す |
| 590ms | 冒頭の文を流し始める（「冒頭の文を流して出す」の節）。冒頭の文がない画面は、ここで全部出す |
| 冒頭の文を流し終えたとき | 残りを一斉に出す。冒頭の文の長さで決まり、上限はない（入口から開く画面で 0.5〜1.8 秒、導入の段2で約 3.4 秒） |

- 押してから実行の行が出るまでは 1 秒未満にする。そのあとは冒頭の文の長さで決まる。待たせすぎないよう、冒頭の文は短く書く（「冒頭の文を流して出す」の節）。
- 2026-11-04 に改めた。前は 590ms に本文をまとめて出し、「合計は 1 秒未満」としていた（見本は Mac の Chrome で 602〜611ms）。冒頭の文を流して出すことにしたので、1 秒未満の決まりは実行の行までに限った。
- 取得が遅いときは入力の行のまま待つ。待っている表示を足さない。
- `prefers-reduced-motion: reduce` では動きを省き、すぐに入れ替える。
- URL を直接開いたとき、ブラウザーの戻る操作で戻ったときは動きを出さない。「戻る」から選んだ移動は動きを出す（「戻る」の節）。
- 読む流れ（聞く、読む）のボタンも打ち込む。入力の行がない画面では実行の行に打ち込む（「押したらターミナルに出す」の節）。前は道具のボタンとして打ち込まなかったが、ユーザーの指示で改めた（2026-11-03）。

### 冒頭の文を流して出す

画面を開いたときは、冒頭の文だけを Claude Code の出力のように数文字ずつ流し、流し終えたら残りをまとめて出す（2026-11-04 のユーザーの判断）。Claude Code でも、流れるのは Claude の言葉で、読んだファイルの中身などはまとめて出る。冒頭の文を「Claude の一言」、残りを `● Read` で読んだ中身として扱う。

| 出すもの | 出し方 |
| --- | --- |
| 冒頭の文のかたまり（最初の帯・枠・ボタンより上にある文。大きな数字「5-3-1-6」も文として扱う） | 上から数文字ずつ足す。1秒に30字 |
| 残り全部 | 冒頭の文を流し終えたら、0.15 秒で薄く浮かべて一斉に出す |

| 画面 | 流す文 |
| --- | --- |
| 入口 | 「「読みます」と言うために。」と「競技かるたにかかわるすべての人に、読みを身近に。」 |
| 総論 | 「5-3-1-6」と「読みの1組は、この配分で15秒です。」 |
| ポイント、最低限、100首の一覧、このアプリについて | 見出し |
| インストール（入れる先を尋ねる画面） | 見出しと、その下の1段落と、小見出し「たとえば」。例のカード、問い、選択肢はまとめて出す |
| AI に入れる手順の画面 | 見出しと、その下の1段落 |
| 練習モード | 見出しと、その下の1段落 |
| 1首、読む、結果 | なし。歌や枠から始まるので、すぐ全部出す |
| まず1回読む の導入 | `●` の文。段1は続けて「5-3-1-6」 |
| 「戻る」の質問 | 「どこに戻りますか？」。選択肢はまとめて出す |

- 経緯：はじめは本文全部を上から流したが、どの画面も 1.5 秒の上限に合わせて速く流れ、せかされる感じになった（同日のユーザーの感想）。そのため冒頭の文だけにした。
- 流しているあいだ、まだ出していないものは場所も取らない。画面はターミナルの出力のように下へ伸びる。
- 速さは1秒に30字で、上限は設けない（2026-11-04 のユーザーの判断）。黙読の速さ（1秒に10字前後と言われる）の約3倍で、目で追える。
  - 経緯：はじめは1秒に60字、上限 1.5 秒にした。ユーザーが試して「ちょっと早い」と感じた。上限を残すと、冒頭の文が長い画面だけ速く流れる（30字にしても、導入の段2は60字ほどに戻る）ので外した。導入の段2は ①② の説明を読んでほしい所なので、ゆっくりでよい。
  - 上限がないので、冒頭の文は短く書く。帯と色を説明していた導入の段2（約95字、約 3.2 秒）は、2026-11-04 になくした。いま一番長いのは、画面を開いたときのインストール（約55字、約 1.8 秒）と練習モード（約51字、約 1.7 秒）である。Gemini に入れる手順は約50字である。字数は見本の `markLead` で冒頭とした文を数えた（2026-11-04）。
- 途中を飛ばす操作は、いまは付けない。操作感を試すため、ユーザーの判断で「1回も飛ばせない」形にした（2026-11-04）。ボタンは残りと一緒に出るので、冒頭の文を流し終えるまで押せない。
- 導入の段の切り替えでは、文の場所を先に取っておき、見えない字から順に見せていく。下の歌の枠が、文の伸び縮みで上下に揺れないようにするためである。
- 「考え方」の「待たせる演出を足さない」とは別に扱う。流すのは出力の見せ方で、AI が考えているように見せる表示（考え中、点滅する点など）は今までどおり出さない。
- 動きを減らす設定（`prefers-reduced-motion: reduce`）、URL を直接開いたとき、ブラウザーの戻る操作では、流さずにすぐ全部出す。

- 録音のあとは `● 録音しました` を出す。実際に起きたことだけを書く。
- URL は英字にする。日本語の URL は共有すると長い文字列になる。Markdown の先頭に `slug` を足す形でよい。
- 組の指定は `?shimo=<札>&kami=<札>` にする。聞く画面と録音の画面で同じ形である。指定がなければ 81番と45番にする。

### 練習モードの組の選び方

「おすすめの組」という考え方は画面に出さない（2026-11-03 のユーザーのコメント）。練習モードの組は次の2つから選ぶ。

- 「ランダムに出題する」（塗りのボタン）：下の句と上の句を、100首の別々の札から選ぶ。打ち込む文字は `読む ランダム` である。
- 「自分で選ぶ」（線のボタン）：100首の一覧へ進み、1首のページの「この札で読む」から始める。選んだ札を上の句にするか、組のもう1枚をどう決めるかは未定である。
- 「まず1回読む」の流れは、導入から読むまで、81番の下の句と 45番の上の句の組にする（2026-11-03 のユーザーの判断）。5-3-1-6 に最も近いお手本の組で、帯とお手本がずれないことを大事にする。前は 77番→29番だった。

### まず1回読む の導入

聞く画面の情報が多すぎ、AI に慣れていない人は投げ出す、というフィードバックを受けた（友人、2026-11-03）。そのため、はじめての人には、聞く画面の中で1段に1つずつ見せるものを増やす導入を出す（ユーザーの案）。総論と内容は重なるが、総論はあとで調べる本、導入ははじめの1回を手を引いて進めるもので、役割が違う。

| 段 | 文（`●` の1行） | 見せるもの | ボタン |
| --- | --- | --- | --- |
| 1 | 競技かるたの読みには、5-3-1-6 というシンプルなルールがあります。 | 「5-3-1-6」の大きな数字と、止まった帯（「5秒」「3秒」「1秒」「6秒」） | 次へ |
| 2 | お手本と一緒に、ルールを確かめてみましょう。 | 組の決まり字と歌の枠 | お手本を聞く。聞き終えると段3へ進む |
| 3 | では、読んでみませんか？ | 同じ | お手本を聞く、読んでみる、「はじめの説明をもう一度見る」 |

- 段は3つにする。前は段2に「このアプリでは、5-3-1-6 の感覚をつかむために、2つの仕組みを使います。」の文を置き、上の帯と歌の後ろの色（地の減り）を ①② の番号と囲みで説明していた。歌の枠から帯と地の減りをなくしたので、説明の段ごとなくした（2026-11-04 夜のユーザーの判断）。
  - この判断は、同じ日の昼の「段は4つのままにし、段2と段3をまとめない」を置き換える。昼の判断は、触ってもらった人の「段2と段3はそれぞれ要る」というフィードバックによる。読む画面で帯と地の減りを使っていた前提でのフィードバックである。
- 文は段が進むと入れ替える。積み重ねると1画面に収まらない。
- 上の帯の右は、段1〜2で「はじめに 1 / 3」のように出し、段3で「1 / 3 聞く」に戻す。
- 導入は初回だけ出す。段3まで進んだら端末に覚えさせ（`localStorage` の `yomimasu.introDone`）、2回目からは段3から始める。覚えられない環境では、毎回段1から出るだけである。
- 「はじめの説明をもう一度見る」で段1へ戻れる。
- どのボタンも、押すとターミナルに打ち込んでから動く（`次へ`、`お手本を聞く`、`はじめの説明`）。再生中の「やめる」は打ち込まずに止める。
- 歌の表記の切り替え（7節「歌に出すもの」）は、段3で歌の面の左上に出す。お手本の再生中は隠す。
- 練習モードには導入を出さない。

### AI に入れる（/インストール）

/yomimasu の読みの知識（スキル `yomimasu`）を、利用者がふだん使う AI に入れるための画面である（2026-11-04 のユーザーの案）。かるたの関係者には、AI エージェントでコードを書く人がほとんどいない。そのため、コーディングエージェントには1行のコマンドを出し、Claude、ChatGPT、Gemini には図を付けて1段ずつ手順を出す。

入口：

汎用の AI の手順（`/install/claude/`、`/install/chatgpt/`、`/install/gemini/`）：

- どれも「ファイルを保存する」「ファイルをアップロードする」「聞いてみる」の段で書く。Claude と Gemini には同じファイル（`/yomimasu.zip`）を配り、ChatGPT にはプラグインの形のファイル（`/yomimasu-chatgpt.zip`）を配る（「保存するファイル」）。Claude だけは、アップロードの前に「クラウドでコードを実行」をオンにする段を入れる。設定の画面に「Skills の使用に必要です」とあるからである。

- 段の見出しの下の文で、押す順を画面の文字のまま書く。図を見なくても進めるようにするためである。

流れの図：

- 「たとえば」の各行は `<details>` にし、開くと、その文を AI に聞いたときの流れの図を出す（2026-11-06 のユーザーの判断）。JS がなくても開け閉めできる。
- 閉じた行は文だけにし、問い「どこに入れますか？」までの距離を延ばさない。開け閉めの印（▸、開くと ▾）は行の左の余白に置き、左右の余白の和は文だけの行と同じ 28px（左 18px、右 10px）にする。文の幅が変わると折り返しが変わり、問いの位置が動く。文が同じなら、閉じた行の問いの位置は文だけの行と同じである（E2E で 320〜393px を確かめている）。
- 図の中は、上から「チャットでの流れの例」、問い（「あなた」）、AI が自分で行ったこと（「スキルを読み込みました yomimasu」「ファイルを読みました …」）、答えの抜粋、確かめた環境と回数の注記の順にする。
- 図のすぐ上に出す聞き方の例が図の問いと違うときは、図の前に、図がどう聞いた例かを断る1行を置く。読む人は、図を上の例を実行した結果と受け取るからである。図の問いは実際に聞いた文の記録なので、聞き直さずに上の例にそろえない（2026-11-07）。断りの1行は図の外の手順の文として置き、図の中は変えない。
- 注記は「Claude Code で確かめた結果（2026-11-04、3回中3回）」の形で、図ごとに付ける。回数は、聞いた回数と、そのうちスキルを読み込んで頼んだ形で答えた回数である。
- 各社の画面の形、ロゴ、画面の文字を写さない。AI が行ったことの行は、Claude Code の道具の呼び出しを言い換えたもので、各社の画面の文字ではない。フォルダーの中を見ただけの呼び出しは省く。
- 答えは実際の答えからそのまま抜き、省いた所は「…」にする。言い換えも、つなぎの語の足しもしない。答えの全文は作業の記録にあり、リポジトリには置かない。抜粋を変えたら、全文と照らし直す。
- 図は画像にせず、HTML の文字で組む。読み上げで読めるようにし、画面の幅で折り返すためである。地は `--paper` にしてカードの文と分け、文字は 14px、見出しと注記は 13px にする。

  - 試したあとで変わったスキルの決まりを、理由に挙げた所。今の決まりのように読める。

## 9. 録音の画面

見本の `/read/rec/` で動かせる。雛形の `recorder.tsx` の `View` を次の状態へ広げる。見本はマイクを開かないので、`starting` がない。

録音の結果は次の形で受け渡す。測定と再生はこの形だけを読む。

```ts
type Take = {
  pcm: Float32Array;
  sampleRate: number;
  readingStartSec: number; // ガイドの時計が動き始めた位置。合図の分を読み飛ばすために持つ
  assisted: boolean;
  pair: { shimo: number; kami: number };
};
```

| 状態 | マイク | ガイドの時計 | ボタン | 次へ |
| --- | --- | --- | --- | --- |
| `idle` | 閉じている | 0 で止まる | 読み始める、補助あり、補助を外す、表記の切り替え（歌の左上）、戻る（8節） | 押すと `starting` |
| `starting` | 開いている途中 | 0 で止まる | やめる | 許可で `count`、拒否で `failed` |
| `count` | 録音中 | 0 で止まる | やめる | 3拍のあと `reading` |
| `reading` | 録音中 | 進む（字の塗りと囲みが動く） | やめる、読み終えた | 読み終えたで結果、25 秒で自動で結果 |
| `failed` | 閉じている | 止まる | もう一度試す、例の録音で見る、教科書へ戻る、戻る（8節） | |

決まり：

- 合図は 3、2、1 を 0.8 秒ずつ、枠の上に数字で出す。音は鳴らさない。録音に入るからである。
- 録音は合図の前から始める。マイクが開く遅れで読みの頭が切れないようにする。
- 測定と再生には、合図の間の音を渡さない。今の測定は録音全体の最も長い無音を間とするので、合図の間の物音や、読み終えたあとのボタンの音で値が大きくずれる。範囲は `Take` の `readingStartSec` から取り、前後の余白は測定の定義で決める。測定に渡す範囲を変えるのは測定の定義の変更なので、`docs/measure.md` を先に直し、スキルも同じ切り方にする（`night` の作業）。
- ガイドの時計は `AudioContext.currentTime` から取る。`requestAnimationFrame` は描くためだけに使う。
- 録音中は右上に赤い丸、「録音中」、経過秒数を出す。色だけで伝えない。
- 「読み終えた」は上の句の区間から押せるようにする。早く押して短い録音になるのを防ぐ。
- ガイドの時計が終わっても（15 秒）、10 秒は録音を続ける。読むのが遅い人の最後を切らないためである。
- 「やめる」を押すと録音を捨てて `idle` へ戻る。
- 録音中に歌詞の位置を動かさない。ボタンの部分の高さを `min-height` で取っておく。見本では開始の前後で座標が同じだった。
- 録音中に別の画面を出さない。リンク、案内、音を足さない。お手本を鳴らさない。
- 持ち方の案内は出さない（ユーザーの判断）。
- 画面が隠れたらやめる扱いにして、マイクを閉じる。録音の画面を離れるときも同じである。
- 録音が終わったらすぐマイクを閉じる。そのあとに再生する。
- `stop` の直後の連打で録音が始まらないよう、雛形の `RESTART_GUARD_MS` を残す。
- 読み直しのときは、実行の行の代わりに1行だけ「直す1点：間を1.0秒にそろえる」の形で出す。行を足すと 360×560 に収まらない。
- 「例の録音で見る」の入口は、`idle` では「読み始める」の右に置く。`failed` では、失敗の理由によらず「もう一度試す」の下に「教科書へ戻る」と並べて置く（11節）。行き止まりを作らない。
- `failed` の案内のカードは、360×560 では1画面に収まっていない。歌の枠が下限の 300px まで縮んでも 93px はみ出し、縦のスクロールで下の行に届く（2026-11-07 に Playwright の Chromium で測った）。収め方は決まっていない（`docs/decisions.md` の 2026-11-07）。

補助を外したとき：

- 字の朱の塗り（余韻の印を含む）と、今の区切りの囲みを出さない（7節「歌の枠」）。
- 歌詞、録音中の表示、「読み終えた」は残す。
- 枠の見出しは「補助なし」にする。
- 結果と記録に補助の有無を残す。

録音の前の説明は、機能に合わせて事実だけを書く。C8 からは「録音は端末に残り、外へ送りません。」と書く。「あとから消せます」は書かない。足すと 360×560 で録音の画面がはみ出すからである。消せることは、前回と比べる画面と「このアプリについて」で伝える（2026-11-06 のユーザーの判断）。

### 余韻の入りを合わせる操作は置かない

余韻に入った瞬間に画面を押すと、ガイドがその時刻から余韻3秒と間1秒を数え直す作りを置いていた（2026-11-03〜04 のユーザーの判断）。下の句を早く読み終えた人が、余韻を無理にのばすか、ずれたまま読み進めることになるのを防ぐためだった。2026-11-04 夜に、ユーザーの判断でこの作りをなくした。

- 理由：「る」を読む瞬間にタップするのは、読む人にはノイズである。字が少しずつ朱になるのはカラオケと同じ理屈なので、たいていの人は余韻の入りも朱の字に合わせられる。押す操作をなくすと、字を追うことと読むことだけに集中できる。
- なくしたもの：
  - タップの受け付け
  - タップの札（「画面のどこかを、「る」でタップ」）
  - 下の句の最後の字の圏点
  - 「● 余韻の入りをタップに合わせました（標準より 0.50秒早い）」の1行
  - `Take` の `yoinTapSec`
- この1行が出ると枠が縮み、歌が約 24px 下がっていた。この問題も一緒になくなった。
- 下の句の最後の字を余韻の始まりに置くこと（7節）は変えない。

### 読む前の説明

初めての人は、「読み始める」を押すとすぐ読むと思い、3・2・1 の合図に戸惑う（2026-11-04 のユーザーの指摘）。そのため、読む画面を初めて開いたとき、歌の枠の上に説明を重ねて出す。読む画面の高さを増やさないためである。

- 出すのは「「読み始める」を押すと、3・2・1 と数えます。数え終わったら読み始めてください。」の1項目だけにする。初めて開いたときも、注記の行の「読み方の説明」で開いたときも同じである。
- 経緯：前は、余韻のタップの説明（2項目目）と、合わせ直す理由（3項目目）を足していた。合わせ直す理由は、触ってもらった人のフィードバックで「読み方の説明」の中だけに移した（2026-11-04）。そのあと、タップの作りをなくしたので、2項目とも消した（同日夜）。
- 合図の文は「3・2・1 と数えます」のままにする。フィードバックの例文は「3秒のカウントダウン」だったが、合図は 0.8 秒ずつで、数え終わるまで 2.4 秒である。
- 「わかった」か「読み始める」を押すと閉じ、端末に覚えさせる（`localStorage` の `yomimasu.recHelpDone`）。2回目からは、注記の行の「読み方の説明」で開く。
- 文は Artifact のコメントで直してよい。

## 10. 録音のあと

### 読み終えたあと

読み終えたら、毎回すぐ結果を出す（2026-11-04 のユーザーの判断）。聴き返し（自分の読み、お手本）と読み直しは、結果の画面に置く。触ってもらった人から、このツールの値打ちは機械が測って評価するところにあり、録音を聞き返すだけならほかの方法でもできる、結果を先に見てからお手本と聴き比べる方が初回は面白い、というフィードバックを受けた。

- 「読み終えた」を押すと `読み終えた` を打ち込み、マイクを閉じ、`Take` を置き場に入れて結果の画面へ移る。結果の画面の実行の行は `/yomimasu 結果を見る` にする。25 秒で自動で止まったときは打ち込まずに移る（8節「押したらターミナルに出す」）。
- 読む流れの上の帯の右は「1 / 3 聞く」「2 / 3 読む」「3 / 3 結果」にする。結果では補助の有無を続けて出す（「3 / 3 結果・補助あり」）。
- 経緯：前は、録音の画面の中で「読めました。まず聴いてみましょう。」の状態（`heard`）を挟み、数値を見る前に自分の耳で確かめさせていた（要件 C5 の「録音のあと、利用者が押すまで結果を出さない」）。この状態はなくした。初回だけすぐ結果を出す案は、初回かどうかで流れが分かれるので採らなかった。

### 結果（C5）

- 行の順は、下の句＋余韻、間、上の句、決まり字までの速さで固定する。
- 1行に、項目名、標準の値、測った値を出す。判定は、判定を出す項目（下の句＋余韻、間、決まり字までの速さ）だけに付ける。上の句には付けない。
- 間の標準の値の欄は「目安」と書き、幅で出す（例：「目安 0.9〜1.2秒」）。値は `docs/measure.md` から取り、ガイドとコードに別の値を書かない。出典は書かない（`REVIEW.md`）。
- 上の帯の右に、補助の有無を「補助あり」「補助なし」と出す。読む流れから来たときは、進み具合に続けて出す（上の節）。
- 次に直す1点の下に、「自分の読み」「お手本」の再生（C6）を置く。塗りのボタンは「次は？」の「もう1回読む」で、測れなかったときは「読み直す」である（見本の結果の画面）。
- 例の録音のときは、「自分の読み」を「例の読み」と書く。利用者が読んだものではないからである。「お手本の読み」にしないのは、同じ画面に「お手本」が並び、例はわざと崩して読んだものだからである（2026-11-06 のユーザーの判断）。
- `Measurement` の型にない項目は行を作らない。決まり字までの速さと音量は、定義と型が入ってから足す。
- 余韻だけの秒数を出さない。
- 音量は行にせず、文の中で参考として出す。「今回の音量は -18 dB でした。参考の値で、端末と持ち方で変わります。」
- 「明瞭さは測っていません。お手本と聴き比べてください。」を必ず出す。
- 「録音は端末の外へ出ません。」を画面の下に出す。動画の段8でも映す。
- 例の録音のときは、先頭に「例の録音です」と出す。

### 次に直す1点（C7）

- カードは結果の行の下に1つだけ置く。
- 見出しは「次に直す1点」、大きな文字は直す内容、その下に理由と直し方を置く。
- 全項目が幅の中なら「今回はありません」として、補助を外して読むことを勧める。
- 測れなかった項目は、1点に選ばない。全部測れなければカードを出さない。
- 「Claude が選びました」と書かない。
- 関わる教科書のページへのリンクを「次は？」に置く。

| ページがない | このページはありません。 | 入口へ戻る（塗りのボタン）。線のボタンで100首の一覧へ |

ページがないときは、配信が `dist/404.html` を 404 で返す（`wrangler.jsonc` の `not_found_handling`）。題は「ページが見つかりません - /yomimasu」で、8節の画面の形の 1、4、5、6 を出す。白い画面を出さない。

値を推測で埋めない。測れない項目は「測れませんでした」と出す。

録音を始められないのは、許可の拒否（`NotAllowedError`）でない理由でマイクを開けないとき、録音の API（`navigator.mediaDevices.getUserMedia`）がないとき、マイクを開いたあとの録音の準備（`AudioContext`、`AudioWorklet`）に失敗したときである。SNS から来た人は、アプリの中のブラウザーで開くことが多い。そこでは開き直しても同じブラウザーで開くことがあるので、ほかのブラウザーを名指しで案内する。録音の失敗の案内には、どの場面でも「例の録音で見る」を置き、録音できない人を行き止まりにしない（2026-11-07 のユーザーの判断）。

### 教科書の出典

資料の名前と版は、ページごとに並べず「このアプリについて」の出典にまとめる（2026-11-06 のユーザーの判断）。資料の出典は消さず、置き場と長さだけを変える。1首のページの札ごとの読み方一覧のページは、歌のすぐ下の短い印で出す（7節「1首のページ」）。

- 項目と助言のそばには短い印だけを付ける。協会の資料は資料の名前とページかスライドの番号だけにする（`冊子 p.4、講習資料 s.29`）。「完全版」は「冊子」と書く（12節）。
- 教科書のページ（ポイントを知る、総論、最低限これだけ、1首のページ）の項目と助言の印は、段落の終わりに `<span class="src">— …</span>` で小さく付け、別の行にしない。協会の資料は `— 冊子 p.3、講習資料 s.8` のようにページを残す。読手のメモは `— 読手メモより`、大会向けは `— 読手メモ（大会向け）より` にする。1つの段落の出どころに協会の資料と読手のメモが並ぶときは、協会の資料を先に書く（`— 読み方一覧（冊子 p.15）、読手メモより`）。印はその段落の全体の出どころを指すので、出どころの違う文は段落を分ける。「ポイントを知る」では、`— このアプリの作者の実体験より`、協会の資料の大会向けの項目の `— 冊子 p.2、講習資料 s.6（大会向け）`、「ん」の説明の中の `— 「ん」の研究（Maekawa 2019 ほか）` と `— このアプリの考え（…）` も使う（2026-11-07 のユーザーの判断。項目ごとの断りがくどく、読む邪魔になるため。同じ日にほかの3ページもそろえた）。読手のメモの文は「メモの読手は…としています」とせず、そのまま書く。メモの番号と項目は画面に出さず、`data-ref` に残す。読手のメモが協会の基準ではなく読手個人のやり方であること、大会向けはふだんの練習会では参考程度であること、作者の実体験は資料にないことは、「このアプリについて」の `#src-memo` と `#src-author` と `#sources` に1か所で書く。
- 印は途中で折り返さない（`span.src` を `inline-block` にする）。文字の大きさと色は `.src`（13px、`--ink-3`）のままにする。
- 別の行の印（`<p class="src">`）は、1首のページの歌のすぐ下の歌の印（7節）と、総論の5・3・1・6の一覧のカードのすぐ下の印（`冊子 p.3、p.26、講習資料 s.8`）の2つだけにする。どちらも段落ではなく、歌とカードの出どころを指す。総論の本文中の括弧の出典（「（講習資料 s.9）」など）は、段落の終わりの印に移さない（2026-11-07 のユーザーの判断。`docs/decisions.md`）。
- ページの終わりには出典の節を置かず、見出しなしの1行（`/about/#sources` へのリンク）を、入力の行の上に置く。総論、最低限これだけ、1首のページは「出典と、読手メモの扱いはこのアプリについてにまとめています。」、「ポイントを知る」は「出典と、読手メモ・作者の実体験の扱いはこのアプリについてにまとめています。」にする。
- 「このアプリについて」の出典は、資料ごとの見出しにアンカーを付ける。`#sources`（節の頭）、`#src-uta`（歌の本文）、`#src-text`（読手テキスト）、`#src-lecture`（講習資料）、`#src-memo`（読手のメモ）、`#src-author`（作者の経験）、`#src-phonetics`（口の形と「ん」の位置の図）、`#src-research`（「ん」を実測した研究）、`#src-audio`（お手本の音声）。marked は見出しに id を付けないので、Markdown の中に HTML で書く。
- 読手、メモの著者、選手の名前は書かない。お手本の読手とメモの著者は、「このアプリについて」にだけ「髙橋A級公認読手」と書く（この節の頭の一覧）。論文の著者名は出典の表示なので書く。読手テキスト完全版 pp.31–32 は使わない。

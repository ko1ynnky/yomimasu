## 2026-11-06 例の録音を配信から取り、利用者の録音と同じ定義でブラウザーの中で測る

- 決めたこと（Issue #44、C9）：
  - `/result/example/` で例の録音の結果を開く。実行の行は `/yomimasu 結果を見る` で（ガイド8節のコマンドの表）、結果の画面と同じ部品で出し、先頭に「例の録音です」と出す（ガイド10節）。
  - 例の音声の URL は `/audio/examples/v1/ma-long.m4a` で、`site/client/example.ts` の1か所に置く。音声はリポジトリに入れず、お手本と同じ R2 の `examples/v1/` に置く。配るのは PR #48 の Worker である。
  - 取った音声をブラウザーの中で PCM に直し、利用者の録音と同じ `measure` で測る。直すときは 48 kHz にそろえ、左右の2本は平均して1本にする。測った値は画面にもデータにも書かない。
  - 例の組は 81番の下の句 → 45番の上の句で、音声と一緒に `example.ts` に置く。読み始めの位置は 0 秒（音声の頭から測る）、補助の有無は「補助なし」にする。
  - 例は IndexedDB に残さず、開いている画面の録音の置き場（`take.ts`）にも入れない。例の画面は利用者の録音を読まず、「前回と比べる」を出さない。
  - 「次は？」の塗りのボタンは「読んでみる」にし、同じ組の録音の画面へ移す。次に直す1点（C7）のカードと教科書へのリンクは、利用者の録音と同じに出す。
  - 音声を取れないとき（置く前の 404、通信の失敗、変換の失敗）は、結果の行を作らず、「例の録音を読み込めませんでした。」と入口へのリンクを出す。
  - 入口の「例の録音で見る」は、録音の画面では「読み始める」の右に、マイクを許可しないときの案内では「もう一度試す」の下に「教科書へ戻る」と並べて置く。録音を始められないとき（マイクがない端末など）の案内には置かない（ガイド11節の表のとおり）。
- 理由：
  - 例と利用者の録音を同じ処理で測ると、定義を変えても例の結果が定義とずれない。測った値を配る形では、定義を変えたときに値が古くなり、音から測ったと言えなくなる。
  - 例を端末に残すと、前回と比べる画面と、間の平均とばらつきに混ざる。
  - 利用者はまだ読んでいないので、「もう1回読む」「読み直す」は合わない。
  - 見本（`docs/ui-sample.html`）は録音の画面の入口を注記の行に置くが、注記の行が2段になり、360×560 で録音の画面が 41px はみ出した（Playwright の Chromium で測った）。393×659 では歌の枠が縮んで収まった。「読み始める」の右に置くと高さは変わらず、読み始めると同じ場所に「やめる」「読み終えた」が並ぶ。
- 採らなかった案：
  - 測った値を JSON などで配る案。上の理由。
  - 変換に AudioContext を使う案。鳴らさないので、出力の装置を開かない OfflineAudioContext で足りる。
  - 例の画面で、開いている画面の録音を出す案。前の結果の部品は、`example` の印があっても開いている画面の録音を出したので、利用者の録音に「例の録音です」が付きえた。
- 例の音声を置くときに要ること：
  - 声の前後に無音を入れる。頭から測るので、測る範囲の最初か録音の最後で声が切れていると「測れませんでした」になる（`docs/measure.md` の `cut-off`）。
  - 配信は v1 の中身を1年キャッシュさせるので、録り直したら名前を変え、`EXAMPLE_AUDIO_URL` を直す。
  - `NOTICE.md` の「音声」に出典を足す（`REVIEW.md` のマージを止める項目）。読んだ人の名前は書かない。
  - 補助の画面を見て録ったら、`example.ts` の補助の有無を直す。
- 限界：
  - 聴き比べ（C6、#34）は、この時点ではなかった（PR #52 で入れた）。C6 は結果の部品が受け取る `take` をそのまま鳴らせばよい。例は IndexedDB にないので、`records.ts` の `loadTake` では読み直せない。例のときは再生のボタンを「自分の読み」と書かない。

## 2026-11-06 録音と結果を端末の IndexedDB に残し、前回と比べる画面を作る

- 決めたこと（Issue #43、C8）：
  - 読み終えたらすぐ、録音（`Take`）と測定の結果を、そのブラウザーの IndexedDB に残す。ログインはなく、端末の外へ送らない（2026-11-02 のユーザーの判断）。
  - 記録と音は別の置き場に分ける。記録には組、補助の有無、録った時刻、測定の結果を入れ、音には PCM、標本化周波数、読み始めの位置、声の処理の設定を入れる。
  - 結果は残すときに1回だけ測り、記録に入れる。一覧を開くたびに測り直さない。
  - `Take` に声の処理の設定（`voiceProcessing`）を入れる。残した録音でも、音量の参考値を出すかを録音ごとにあとで決められるようにするためである。`measure` に `autoGainControl` を渡さないのは今までどおりで、音量の参考値は出さない（`docs/measure.md`）。
  - 前回と比べる画面は、ガイド8節のコマンドの表のとおり `/result/compare/`（`/yomimasu 前回と比べる`）に置く。
    - 新しい2件を前回と今回として、結果の画面と同じ行、目安、判定の語で並べる。組が違っても並べ、列の見出しに組の決まり字と補助の有無を出す。
    - 前回と今回の録音を、読み始めの位置から鳴らせる。
    - 間の平均とばらつきは、間を測れた回が2回以上あれば、残っている全部の録音から出す。平均は 0.01 秒の値から求め、0.1 秒に1回だけ四捨五入する。ばらつきは、いちばん短い回と長い回の差である。どちらも判定の語を付けない。
    - 録音は1件ずつと全部を消せる。全部を消すときだけ、消す前に確かめる。
  - 結果の画面は、開いている画面の録音がなければ、端末に残した最後の録音を出す。ただし、最後に読んだ録音を残せなかったときは、前の録音を出さない。残せなかったことは sessionStorage に覚える。
  - 録音が1件でも残っていれば、結果の画面の「次は？」に「前回と比べる」を置く。
  - 録音の画面の注記を「録音は端末に残り、外へ送りません。」にする（ガイド9節）。「あとから消せます」は書かない。
  - 2026-11-06 の朝に、ユーザーが次の3つを認めた。注記に「あとから消せます」を書かないこと。「前回と比べる」を、録音が1件のときから出すこと。1件ずつ消すときは確かめず、全部を消すときだけ確かめること。
- 理由：
  - 1本を測るのに、23秒の合成音で約 90 ms かかった（Node、M5 の Mac、3回）。端末ではこの数倍かかるので、一覧を開くたびに全部を測り直すと待たせる。
  - 音を記録と同じ置き場に入れると、一覧を開くたびに、1本で約 5 MB（27秒、48 kHz、32 ビット）の音を全部読み込む。
  - ばらつきを最短と最長の差にしたのは、2〜3回でも値が揺れにくく、選手と保護者に「1.0〜1.6秒」の形で伝わるからである。差は見せる 0.1 秒の値どうしで取り、並べた秒と食い違わないようにした。
  - ばらつきに判定の語を付けないのは、ばらつきの幅の目安が測定の定義にないからである。新しい目安を決めるのは測定の定義の変更になる。
  - 「前回と比べる」を前回の録音がないうちから出すのは、録音を消す操作がその画面にしかないからである。出さないと、録音が1件のうちは消せない（reviewer の指摘）。
  - 注記に「あとから消せます」を足すと、360×560 で録音の画面が 41px はみ出した。注記と「読み方の説明」が1行に収まるのは 18 字までである。
  - 残せなかったことを覚えないと、ページを読み込み直して結果の画面へ移ったときに、前に残した録音の結果を今回の結果として出す（reviewer の指摘）。
- 採らなかった案：
  - 一覧を開くたびに、残した音から測り直す案。定義が変わったあとも同じ定義で並べられるが、上の理由で待たせる。定義が変わったら、残した音から測り直せる。
  - ばらつきを標準偏差で出す案。2〜3回では揺れやすく、伝わりにくい。
  - 平均とばらつきを、補助の有無や組で分ける案。回数が少ないうちは分けると出なくなる。
  - `navigator.storage.persist()` で消されにくくする案。Firefox は許可を尋ねる画面を出すので、読む流れを止める。
  - 残す件数に上限を設け、古い録音を自動で消す案。利用者が消していない録音を消すことになる。
  - PCM を 16 ビットや低い標本化周波数にして小さくする案。測り直したときに値が変わる。
  - 1件ずつ消すときも確かめる案。消す操作が多いと手間になる。消すのは1件だけなので、全部を消すときだけ確かめる。
  - 前回の録音があるときだけ「前回と比べる」を出す案。はじめはこの形にしたが、上の理由で改めた。
- 限界：
  - 残せる量はブラウザーと端末の空きで違う。残せなかったときは知らせず、記録の画面に出ないだけである。
  - Safari は、しばらく開かれないサイトがスクリプトで残したデータを消すことがある。iPhone の実機ではまだ確かめていない。
  - 前回と比べる画面の再生は、この時点ではお手本の再生（PR #22 の `playback.ts`）と1つにしていなかった（PR #52 で1つにした）。
  - 前回と比べる画面にも、ほかの画面と同じく「戻る」とターミナルへの打ち込みはまだない。
  - 記録には、どの定義で測ったかを入れていない。定義が変わると、前の定義の値と今の定義の値を同じ表と平均に並べる。定義を変えるときに、記録に定義の印を足し、印のない記録を残した音から測り直す。
  - 平均とばらつきの決め方は `site/client/compare.ts` にだけあり、`docs/measure.md` とスキルの `scripts/` にはない。この Issue で触ってよい範囲の外なので、置き場はユーザーが決める（reviewer の指摘）。

## 2026-11-06 お手本の音声を、公開しないバケットから Worker が同じオリジンで配る

- 決めたこと：
  - お手本の202本は R2 のバケット `yomimasu-audio` に `v1/NNN_N.m4a` の名前で置き、バケットは公開しない。アプリの Worker（`site/worker.ts`）が、同じオリジンの `/audio/v1/NNN_N.m4a` で配る。
  - Worker を静的なファイルより先に通すのは `/audio/*` だけにする（`assets.run_worker_first`）。静的なファイルに当たらないパスは Worker にも来るので、`/audio/` の外は `ASSETS` の束縛に渡し、今までどおりの答えにする。
  - 答えるのは GET と HEAD の `/audio/v1/<3桁>_<1か2>.m4a` だけにする。形の違うパスは、バケットにキーがあっても 404 にする。形の合うパスへのほかのメソッドは 405 にし、`Allow: GET, HEAD` を付ける。
  - Range は1つの範囲に 206 で答え、満たせない範囲には 416 と `Content-Range: bytes */全体の大きさ` を返し、長いキャッシュは付けない。複数の範囲と読めない Range は、RFC 9110 が認めるとおり無視して全体を返す。
  - `Content-Type: audio/mp4`、`Cache-Control: public, max-age=31536000, immutable`、`Accept-Ranges: bytes` は、バケットのメタデータを写さずに Worker で付ける。ETag は R2 の `httpEtag` を使う。
  - `v1/` のキーの中身は置き換えない。音声を直すときは `v2/` のキーに置き、聞く画面の取得先を変える。
  - プレビューにも同じバケットを束ねる。
- 経緯：2026-11-06 にユーザーが、お手本の音声を上げて配ることを決めた（#42）。
- 根拠：
  - 聞く画面は、取得先を同じオリジンのパスに限る（PR #22 の `site/client/playback.ts`）。外の配信から読むと、どの端末が聞いたかが外へ出るからである。
  - Range は iOS の Safari が使う（#42）。
  - パスの形で m4a に限っているので、型は Worker で決められる。上げ方の違いで型やキャッシュが変わらないようにした。
  - キーの中身を置き換えないので、1年の `immutable` で端末にキャッシュさせても古い音が残らない。同じ理由で、`If-None-Match` と `If-Range` は見ない。
  - R2 の Workers API の文書は、満たせない範囲を `get` に渡したときの答えを決めていない。そこで範囲の要求では先に `head` で大きさを見て、範囲を Worker で決めてから `get` で読む。
  - プレビューは、上の階層の束縛を受け継がない。束縛は `previews` に書く。Worker はバケットを読むだけなので、プレビュー用のバケットには分けない。
- 採らなかった案：
  - バケットを公開し、r2.dev の URL で配る案。別のオリジンになり、聞く画面の取得先の制限から外れる。r2.dev は速さが制限され、本番には向かない。
  - バケットを公開し、カスタムドメインで配る案。これも別のオリジンになり、CORS の設定が要る。バケットの中のどのキーも、パスの検査なしに取れるようになる。
  - 音声を `dist` に入れて静的なファイルとして配る案。音声は Git に入れない（2026-11-02）ので、組み立てのたびにどこかから取ってくることになる。
  - R2 の型のために `@cloudflare/workers-types` を足す案。使うのは `head` と `get` だけなので、使う形だけを `site/worker.ts` に書き、依存を増やさない。
- 限界：
  - Worker の答えは Cloudflare の CDN のキャッシュに載らないので、毎回 R2 から読む。端末のキャッシュは1年である。要るようになったら Cache API を試す。
  - 範囲の要求は R2 の操作を2回使う（`head` と `get`）。
  - iPhone の Safari での再生は、PR #22 のマージのあとに、プレビューの聞く画面で確かめる。
  - お手本の許諾を得た日は、まだ `NOTICE.md` の「音声」にない。ユーザーが書き足す。
- 根拠の文書（確認日 2026-11-06）：[Static Assets の routing](https://developers.cloudflare.com/workers/static-assets/)、[run_worker_first](https://developers.cloudflare.com/workers/static-assets/routing/worker-script/)、[Previews の設定](https://developers.cloudflare.com/workers/previews/configuration/)、[R2 の Workers API](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/)、[R2 の制限（r2.dev）](https://developers.cloudflare.com/r2/platform/limits/)、[RFC 9110 の Range](https://www.rfc-editor.org/rfc/rfc9110#section-14.2)

## 2026-11-05 余韻の最後の音の口の形と「ん」の位置を、一般の音声学と研究から図にする

- 決めたこと：
  - 教科書の「ポイントを知る」の作者の経験のカード（最後の音ごとに弱め方を練習する）に、あ・い・う・え・お・ん の口の形の図を6つ並べる。1首のページには、その札の最後の音の図を1つ出す。どちらも正面から見た唇と、横から見た口の中のスケッチで、弱めて消す間に保つ所を添える。
  - 同じカードの中の折りたたみに、「ん」の断面のスケッチと研究の要点を入れる。舌が上あごに付く所は、歯茎から口蓋垂までの帯で幅として描き、1点に決めない。唇を閉じる例は点線の囲みで示す。「ん」で終わる札の1首のページは、この折りたたみ（`/point/#yoin-n`）へ案内する。

  - 「ん」で終わる札の数と内訳は、教科書では組み立てのたびに表から数える。スキルの `references/mouth-shapes.md` には数と内訳を書き写し、`test/skill/mouth-shapes.test.ts` が表と照らす。`timing.md` の最後の音の数は答えるときに表から数える決まりだが、「ん」の内訳は最後の2字をまとめて前の音の母音に当てる手間があり、コードを動かせない AI では数え違えやすいからである。保つ所の表も、教科書の図の文と照らす。

  - 読み始めの位置ちょうどから測る案。帯が動くのと同時か少し前に出た声の頭が切れる。
  - データを JSON に置く案。値ごとに採らなかった案を書けず、選べる値を型で縛れない。

## 2026-11-03 平日の昼に自走を順に進める

## 2026-11-02 CI の検査を決める

## 2026-11-02 アプリの技術を決める

- 決めたこと：
  - 枠組みは、Vite、Markdown から HTML を書き出す小さな生成スクリプト、録音と結果の画面の Preact にする。出力は Cloudflare Workers の静的アセットとして配る。
  - 測定は TypeScript で書く。共有コードは `.claude/skills/yomimasu/scripts/` に置き、Web はそのファイルを読み込み、スキルは Node か Bun で型を除いて動かす。
  - 録音は AudioWorklet で PCM を受ける。MediaRecorder は実機で AudioWorklet が使えないと分かったときの代わりとして残す。
  - お手本の音声は AAC の m4a にする。測定に通す音は WAV にして、自分のコードで読む。
  - 測定の結果は 0.01 秒の単位に丸めてから返す。
  - 依存は `preact`、`vite`、`marked`、`typescript`、`@types/node`、`wrangler`、`@playwright/test` の7つにする。この Mac に pnpm がないので、パッケージの管理は npm で行う。
  - 公開は `production` ブランチだけにし、それ以外のブランチは Worker Previews に出す。

## 2026-11-02 音声と鍵の書き込みを hook で止める

- 決めたこと：`.claude/settings.json` の PreToolUse の hook で、Write、Edit、NotebookEdit、Bash を検査する。リポジトリの中へ音声や鍵のファイルを書く操作と、鍵らしい文字列を含む操作を止める。

- 試行錯誤：最初の実装はリポジトリの中のパスだけを見ていて、`cp /外/a.wav tests/` を通した。音声の名前がコピー元にしか出ないからである。先に書いたテストで見つかり、コピー系のコマンドは最後の引数をコピー先として扱う形に直した。
- 試行錯誤：直したあとも、`cp /外/a.wav tests/ 2>/dev/null` を通した。最後の引数が `/dev/null` になるからである。セルフレビューで見つかり、リダイレクトを除いてからコピー先を決める形に直した。

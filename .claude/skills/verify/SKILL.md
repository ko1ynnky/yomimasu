# 動かして確かめる

順に実行し、各段の完了の条件を満たしてから次へ進む。失敗したら直してから、その段をやり直す。

## 1. 動かせる状態かを見る

```bash
test -d node_modules || npm ci
npx playwright install chromium
lsof -nP -iTCP:8799 -sTCP:LISTEN
```

完了の条件：`node_modules` があり、Chromium が入っていて、8799番を使うプロセスがない。

8799番を使うプロセスが自分で起動したものなら止める。心当たりのないプロセスは止めず、ユーザーに伝える。

## 2. 静的に確かめる

```bash
npm run check
```

完了の条件：exit 0 で終わり、テストの `fail` が0件である。

## 3. 利用者の経路で動かす

```bash
npm run e2e
```

Playwright が組み立てと `wrangler dev` の起動と停止を行う。Chrome の偽のマイクに合成音を渡し、ボタンを押して、画面に出た秒数を正解と比べる。

完了の条件：全件が `passed` である。

触った機能が [features/README.md](features/README.md) にあれば、その機能のファイルの全項目を確かめる。機能を足したら、`e2e/` にテストを足し、一覧にも足す。

## 4. 証拠を読む

`e2e-artifacts/` の `.json` と `.png` を開き、自分の目で確かめる。

- `.json` の `expectedMaSec` と `shownMaSec` が 0.05 秒以内である。
- `.png` に、測った結果か、測れなかった理由が出ている。

完了の条件：すべての結果を読み、画面が意図どおりだと確かめた。

合成音の結果は、測定の処理が動くことを示す。測定の定義が実際の読みに合うことは示さない。

## 5. 確かめられないことを分ける

次はこの手順では確かめられない。報告に「確かめていない」と書く。

- iPhone の Safari と Android の Chrome の実機の録音
- 実際の声での測定の精度
- 本番とプレビューの配信

## 6. 報告する

実行したコマンドと出力、読んだ証拠、確かめていないことを書く。PR の「E2E の成果物」の欄には `e2e-artifacts/` の画面の画像と合成音の結果を貼る。

## 片付け

`npm run dev` を自分で起動していたら、そのプロセスだけを止める。`e2e-artifacts/` は証拠なので消さない。
